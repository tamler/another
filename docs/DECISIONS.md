# Another decisions

Locked defaults for v1 (2026-10-28). See [SPEC.md](SPEC.md) for the full research and design.

| Decision | Choice | Notes |
|---|---|---|
| License | **Apache-2.0** | Patent grant; company-friendly; matches `rmcp` / A2A / Herdr. |
| Agent names | **Unique per project** | Addressed as `name@project` (an agent registered without a project is just `name`). A bare `name` resolves when exactly one agent on the node has it; otherwise it is rejected as ambiguous and callers must use `name@project`. Across nodes (M5): `name@project@node`, or `name@@node` for agents without a project. |
| Database location | **`~/.another`** (override with `$ANOTHER_HOME`) | One local node database; not per-repo. |
| Beads | **Deferred** | Keep requests inside Another for now; revisit linkage later. |
| Stack | **Rust + official `rmcp` + SQLite** | Single static binary; hooks stay tiny shell scripts. |
| Wake strategy | **Hooks-first** | Claude Code, Grok, Codex (Cursor best-effort). Herdr / cmux / tmux are optional adapters, not required for core. |
| Business model | **Free and open source, always** | Every feature (including federation) ships in the open repo. No paid tier, no paid hosted relay, no open-core upsell. Self-hostable hub; community-run relays optional. |
| Binding | **Loopback by default** | Loopback / stdio by default. From M4, a non-loopback bind needs both `--auth` and `--allow-remote-bind`; tunnels to a loopback `--auth` server are preferred. |
| MCP surface | **Small, additive** | M1: `ensure_project`, `register_agent`, `send_message`, `fetch_inbox`, `threads`, `acknowledge`, `claim_request`, `hold_paths`, `heartbeat` (9; `threads` added to the ~8 suggested). M2 adds `activity_feed`, `activity_summarize` (11). M3 adds `resource_register`, `resource_find`, `resource_borrow`, `resource_release`, `resource_heartbeat`, `orphans_list`, `resource_reap` (18). |

Clean-room: implement from this repo's docs only. Do not copy code or schemas from MCP Agent Mail or any project with a non-permissive license rider.

## Milestone decisions

Design calls not covered by SPEC, recorded as they were made.

| # | Milestone | Decision |
|---|---|---|
| D1 | M2 | **Activity feed never carries message bodies.** Items are one-line summaries plus ids, so any peer (including a remote Grok Bot later) can read the feed without seeing mail content. |
| D2 | M2 | **Plain heartbeats are presence, not events.** `session.started` / `session.ended`, hold renewals and every other mutation are logged; a bare heartbeat only updates `last_seen_at`, so per-prompt hooks do not flood the log. |
| D3 | M2 | **Default hook identity is `<client>@<project>`** (project = nearest git root of the client's cwd), auto-registered on first use; `$ANOTHER_AGENT` overrides. Same rule for every client. |
| D4 | M2 | **Grok de-duplication.** Grok also runs Claude/Cursor hook files. An Another hook invoked under Grok (`GROK_HOOK_EVENT` set) acts as `grok` and stands down when the Grok pack is installed, so each event runs once. |
| D5 | M2 | **Cursor is best effort.** Its prompt hook cannot inject context, so only session start carries the digest there; the prompt hook renews holds and returns `{"continue": true}`. |
| D6 | M2 | **Prompt notices are once per message.** The last announced message id per agent is kept in `$ANOTHER_HOME/hooks/state/`, so repeated prompts do not repeat the same notice. |
| D7 | M2 | **Hook installer edits user-level configs only**, refuses invalid JSON or foreign files, backs up before writing, and is all-or-nothing across the clients requested. Project-level hook files are left to the user. |
| D8 | M3 | **Reaping is human-only.** MCP `resource_reap` returns a plan and logs `resource.reap_requested`; it never signals a process. Only `another reap --confirm` (CLI) terminates, after a grace period (default 10 min), for the current user's non-system processes; SIGTERM first, SIGKILL only with `--force`. There is no auto-reap. |
| D9 | M3 | **Lapsed resources stay listed.** A resource with no live lease is an orphan candidate, not deleted; registering or borrowing it again adopts it. `release --stopped` (owner) marks it gone. |
| D10 | M3 | **Ownership passes to the oldest borrower** when the owner releases a shared resource others still use. |
| D11 | M3 | **Session end releases holds and resource leases.** `heartbeat --end --keep` keeps resource leases (servers meant to outlive a session); holds are always released. |
| D12 | M3 | **Orphan scan** uses `lsof` (macOS first, also Linux) with `ss` as a fallback and `ps` for age/command; system daemons and Another are allowlisted out. Reaping by pid is limited to unregistered listeners the scan finds; registered resources are reaped by id. |
| D13 | M3 | **Resource leases** default to 30 minutes, clamped to 1 minute-24 hours (holds stay 1 minute-4 hours). |
| D14 | M4 | **Tokens act as one agent within project globs.** Secrets are `ano_<id>_<random>`; only a SHA-256 hash is stored and the secret is printed once. No globs means no project access (mailbox, heartbeat and feed still work). |
| D15 | M4 | **`--auth` verifies every request, including loopback ones**, because tunnels (Tailscale Serve, cloudflared, `ssh -R`) deliver from loopback. Run local agents on a separate unauthenticated loopback server or stdio. |
| D16 | M4 | **Feed, summary and `resource_find` are node-wide read-only awareness for any token** (the feed carries no bodies); mailbox, holds, requests and resource leases are scoped. `orphans_list` never runs a process scan for remote callers. |
| D17 | M4 | **`resource_reap` is refused for every remote caller**, regardless of token scope. |
| D18 | M4 | **Audit log is separate from the event log**: node-local security records (not synced), arguments redacted (bodies and notes replaced by their size). Denied and unauthenticated requests are logged too. |
| D19 | M4 | **No built-in TLS.** Remote access goes through a tunnel or reverse proxy that terminates TLS; `--allowed-host` names tunnel hostnames for DNS-rebinding protection. |
| D20 | M5 | **Ed25519 node keys; every event signed by its origin.** Older databases get a key on upgrade and their events are signed then. Hubs pin a spoke's key at pairing; spokes trust the hub's node directory (hub-and-spoke trust). |
| D21 | M5 | **Agent addresses are stored** (`agents.address`) so foreign agents read as `name@project@node` everywhere (from/to, owners, leases) and replies route unambiguously. Acting identities must be local; recipients and filters may be remote. |
| D22 | M5 | **Routing classes**: directory events to every peer; mail only to recipient nodes (local-only mail never leaves its node); receipts to the message's node; activity to `read_feed` peers plus the owner of a borrowed resource; tokens, audit and pairing records never. |
| D23 | M5 | **Hub enforces permissions on push** (a spoke may only push its own events; `send_mail` for cross-node mail; `borrow_resource` for borrowing other nodes' resources). Rejected events are reported and skipped so the spoke's cursor still advances. |
| D24 | M5 | **Requests are node-local.** Opening a request with a recipient on another node is refused; plain mail works. |
| D25 | M5 | **Remote resources**: reachability is a TCP connect from this machine to the endpoint; foreign leases count until their TTL even if the borrower goes offline; stop/reap only on the owning node; a lapsed remote resource can only be adopted on its node. |
| D26 | M5 | **Cross-node hold clashes are warnings**, matched by project slug (repository name) since paths differ between machines. |
| D27 | M5 | **Node names must be unique** in a federation and set before pairing (`another node name`); the default `local` cannot pair. |
| D28 | M5 | **Hub reads relayed mail bodies** (self-hosted hub; end-to-end encryption deferred). Node-to-node requests are signed and time-bounded (±5 min); replays are harmless because push is idempotent and pull is read-only. |
| D29 | M6 | **Wake adapters are optional extras on top of hooks**: `tmux send-keys`, `cmux send --surface` / `cmux notify`, `herdr agent prompt`, run as argv (no shell, no linking; cmux is GPL and only ever invoked as a separate CLI). |
| D30 | M6 | **Wake only when something is waiting** (unread mail or open requests) unless `--force`; the message is a one-line summary with subjects, never bodies. |
| D31 | M6 | **Wake targets are stored per agent**; session hooks auto-capture `$TMUX_PANE` / `$CMUX_SURFACE_ID`, and automatic captures never replace a target set by hand. Herdr targets default to the agent's bare name. |
| D32 | M6 | **Linux release binaries are static musl** (x86_64, arm64) so one archive runs on any distro; macOS ships arm64 and x86_64 (unsigned; remove quarantine with `xattr`). Releases publish only from `v*` tags; PRs touching the workflow build without publishing. |
| D33 | M6 | **Herdr plugin uses documented manifest fields only** (`[[actions]]`, `[[panes]]`, argv commands) and calls the `another` CLI; `min_herdr_version` is a best-effort floor. |
| D34 | v0.1.0 | **Hook installs preserve config permissions.** Every config rewrite (install and uninstall, all clients) writes a fresh temp file created `0600`, copies the original file's mode (and owner/group where the OS allows) onto it, then renames it into place; new configs are `0600`. Symlinked configs are written at their target so the link survives. Found by a macOS smoke test where `~/.claude/settings.json` went from `0600` to `0644`. |
| D35 | v0.1.0 | **Renamed from Wyres to Another** before the first release (home: [toanother.one](https://toanother.one); repo `github.com/tamler/another`; tagline "From one agent to another."). Why: a clearer name, a matching domain, and no clash with the WyreUp file-tools brand. Another is its own product, not a WyreUp sibling. Clean rename with no compatibility aliases (nothing had been released): crate and binary `another`, data dir `~/.another`, `ANOTHER_*` env vars, `another-hook.sh`, the `another.inbox` Herdr plugin, `another-*` protocol strings and headers, and `ano_` token prefixes. The only exception: `another hook install` / `uninstall` still recognise the old `wyres-hook.sh` entries and `~/.grok/hooks/wyres.json`, so development installs clean themselves up. |
| D36 | connectors | **OAuth 2.1 authorization server is part of `another serve --auth`** when `--public-url` is set (MCP authorization spec 2026-07-28). Protected-resource and authorization-server metadata, S256 PKCE, the RFC 8707 `resource` parameter, and RFC 9207 `iss` on every redirect. Clients may use a Client ID Metadata Document or dynamic registration; only public clients (`token_endpoint_auth_method=none`) are accepted. A grant is created only by `another oauth approve` on the machine that holds the database. There is no HTTP approval. The grant acts as exactly one agent within project globs, the same rule as a bearer token. Access tokens last one hour. Refresh tokens rotate, and presenting a replaced refresh token revokes the grant. The authorization code and the one-time redirect token are stored only as SHA-256 hashes. The code is minted in the server process on the first poll after approval and returned once in that redirect. Bearer tokens keep working. The public origin is whatever tunnel the operator configures. Nothing in the binary names a domain. `whats_new` is the one-call catch-up for a hosted chat app (subjects and ids, never message bodies). |
| D37 | connectors | **ChatGPT desktop uses a local MCP client. ChatGPT web plugins do not.** The desktop app, Codex CLI, and IDE extension share `~/.codex/config.toml` and can start a stdio process or connect to a Streamable HTTP URL on this machine, including loopback. That path does not need a tunnel or OAuth. Developer-mode custom connectors are a different path: ChatGPT on the web calls a public HTTPS URL or a Secure MCP Tunnel, and the desktop app does not apply the local Codex config to those hosted chats. Prefer stdio (`another serve --stdio`) for the desktop app. |
| D38 | connectors | **DNS-rebinding checks cover every HTTP route except `/fed`, including unauthenticated loopback.** `Host` must be `localhost`, `127.0.0.1`, or `[::1]` with the bound port, or an explicit `--allowed-host` / `--public-url` host. An allow-list entry with no port matches only a Host header with no port. A state-changing request (POST, PUT, PATCH, DELETE) that sends `Origin` must match an allowed origin exactly (the loopback `http` origins on the bound port, or the `--public-url` issuer). No suffix match. Missing `Origin` is allowed, so non-browser clients are unchanged. `/oauth/token`, `/oauth/register`, and `/authorize` share an in-memory token bucket per client IP and answer `429` with `Retry-After`. A refresh token is issued only when the grant's scope includes `offline_access`. |
| D39 | dashboard | **The dashboard is embedded and loopback-only.** Static HTML, CSS and JS ship inside the binary (no runtime build, no CDN, no telemetry). `another serve` on loopback without `--auth` serves it at `GET /ui`. `another dashboard` starts a dashboard-only server on `127.0.0.1:7468` (so it does not take 7466 or the `--auth` example port 7467) and opens a browser. It reads the same SQLite database. |
| D40 | dashboard | **`--auth` does not serve the dashboard unless `--dashboard` is passed, and a non-loopback bind never does.** Tunnels terminate on loopback (D15), so an authenticated server is treated as remote. With `--dashboard` on that server the view is read-only and message bodies are omitted; actions are not mounted. `--dashboard` on a non-loopback address is refused. The dashboard still requires a loopback `Host`, even when `--allowed-host` or `--public-url` would let the rest of the server use a tunnel name. |
| D41 | dashboard | **Message bodies are a local-dashboard privilege.** The unauthenticated loopback UI shows bodies of messages authored on this node. Messages from other nodes stay redacted. `GET /activity` still carries summaries only (D1), and the audit log still replaces bodies with their size (D18). A redacted dashboard does not search bodies either. |
| D42 | dashboard | **Two local actions, both confirmed.** Release a hold only when its owner is away (offline, or idle for 30 minutes) or stale. A conflict, including a cross-node clash, does not make a live owner's hold releasable. Mark an open or claimed request stale ("expire"). Each needs `{"confirm": true}`, `X-Another-Confirm: 1`, and an `Origin` of `http://` plus a loopback host on the exact bound port. A different port is refused. The event reason is `dashboard`. Neither action touches another node's holds or requests. |
| D43 | dashboard | **Dashboard requests must name a loopback Host.** `127.0.0.1`, `localhost`, and `[::1]`, with or without a port, or the exact address this process bound. `+80` and `0080` are not ports. A DNS rebinding page arrives on the loopback socket with a foreign `Host`; `/ui`, the read APIs, SSE, and both action POSTs refuse it. This applies to `another serve` and `another dashboard`, including `serve --auth --dashboard`. It does not accept a tunnel host that D38 would allow. |
| D44 | dashboard | **Presence is derived.** `live` means status `active` and seen within 10 minutes, or `active` with no last-seen time yet. `idle` means `active` and seen within 6 hours; otherwise `offline`. Offline and last seen more than a day ago is **stale** and hidden until the human asks. An unknown hold owner is not offered Release. A plain heartbeat is still not an event (D2). |
| D45 | push-holds | **Mid-task delivery is a `post-tool` hook, not a daemon round trip.** Claude Code, Codex and Grok run it on `PostToolUse` for every tool; Cursor on `postToolUse`. It reads the database directly (no write on open, no migration, 50 ms lock wait), uses the same once-per-message cursor as prompt notices (D6), and prints nothing when nothing is new. Any channel that announces a message (mid-task notice, prompt notice, daemon wake) marks it announced for the others. At most once a minute it marks the agent active and renews only holds past half their TTL, so long prompt-less tasks keep their holds without a `hold.renewed` event per tool call. |
| D46 | push-holds | **Holds are enforced by a `pre-edit` hook on client edit tools.** Claude Code and Grok match `Edit\|Write\|MultiEdit\|NotebookEdit`; Codex matches `apply_patch\|Edit\|Write` and the file names come from the patch headers. Each edited file gets a narrow exclusive hold (default TTL, reason "editing (taken by the edit hook)") unless an own exclusive hold already covers it; a conflicting hold of another agent denies the edit with the holder, pattern, project and expiry named, and suggests `another send --request`. The hook never answers "allow", which would skip the client's permission prompts. Cursor gets no edit guard: it blocks a tool call on a non-JSON `preToolUse` reply, and a fail-open hook prints nothing. Shell-command edits are out of reach of every client's edit hook. |
| D47 | push-holds | **Fail-open policy.** Push always fails open (silent, exit 0). The edit guard denies only a conflict it actually found; when it cannot check (missing or locked database, 300 ms lock wait, old schema) it allows the edit and appends a line to `$ANOTHER_HOME/logs/hooks.log` (capped at 256 KB, one rotated copy). |
| D48 | push-holds | **Holds conflict across checkouts of one repository.** A node-local cache table, `project_repos`, links each local project to a repository key read from files only (no git process): the `origin` URL reduced to `host/path` with scheme, credentials, port and `.git` removed, else the shared git directory. Conflicts compare repository-relative paths, so sibling worktrees, separate clones and subdirectory projects collide. The cache is derived from this disk, so it is not an event and never syncs; cross-node clashes stay warnings matched by slug (D26). Projects from before the cache are linked the first time their holds are checked. |
| D49 | push-holds | **Whole-project holds need `--repo-wide`.** `**`, `.`, the project root, and any glob that starts with a wildcard and contains `**` (such as `**/*.rs`) are refused by `hold acquire` and MCP `hold_paths` unless `--repo-wide` / `repo_wide: true` is given. Existing broad holds keep working, and `hold check` accepts broad patterns since it takes nothing. |
| D50 | push-holds | **The loopback daemon wakes idle Herdr agents.** `another serve` without `--auth` checks every 2 s for unannounced mail on Herdr targets, waits 2 s for a burst to settle, asks `herdr agent get <pane>`, prompts only `idle`/`done` agents with `herdr agent prompt`, leaves `working` ones to `post-tool`, never interrupts `blocked` ones, and waits 60 s before waking the same agent again. Herdr is only called with a subcommand and never to focus. tmux and cmux are not woken automatically because they cannot report whether the agent is busy. `--no-wake` turns it off; an `--auth` server never runs it, so two servers do not wake the same agent. |
| D51 | push-holds | **Wake targets follow the session.** Session start captures `$HERDR_PANE_ID` as well as `$TMUX_PANE` and `$CMUX_SURFACE_ID`, with `TERM_PROGRAM` choosing the innermost of nested multiplexers. Session end forgets an automatic capture that still names its pane. `another wake prune` (and the daemon every 10 minutes) drops automatic targets whose pane is gone (Herdr `agent_not_found`, tmux pane missing) or whose agent ended its session or was not seen for 24 hours. Targets set by hand are never pruned. |
| D52 | push-holds | **`another daemon` manages a launchd LaunchAgent on macOS only.** Label `one.toanother.another`, `another serve --bind <loopback>`, `RunAtLoad` and `KeepAlive`, `ANOTHER_HOME` and the installing shell's `PATH` recorded, log at `$ANOTHER_HOME/logs/serve.log`. `serve` stops cleanly on SIGTERM as well as Ctrl-C. Other systems run `another serve` under their own service manager. |
| D53 | push-holds | **Coordination evidence is counted from the event log.** The edit guard writes `hold.blocked` (stopped agent, holders, paths, projects, repository key); its holds carry `auto: true`; notices write `push.notified` (channel `post_tool` or `prompt`, message ids); daemon wakes write `push.woke` (pane, outcome, message ids). `another stats --since <time>` counts these plus requests created, claimed and completed, and how many pushed messages the same agent later read, acknowledged or answered. Recording is best effort: a notice or wake still happens if its event cannot be written. |
| D54 | push-holds review | **Announcements are claimed in the database.** A node-local `announcements` table (migration v8) holds one row per agent and message. Every channel reads unannounced mail, then claims it with `INSERT OR IGNORE` in one transaction that also writes the `push.notified` evidence, and shows only what it won. This replaces the per-agent cursor file (D6), whose sanitized names let `a.b` and `a_b` collide. The daemon claims after the Herdr probe and gives the claim back if the wake fails. A notice claims up to 1000 messages, so a burst is counted in full. Mail unread at upgrade time is announced once more, since there is no claim row for it yet. |
| D55 | push-holds review | **The edit guard and manual holds resolve symlinks.** Existing path components are resolved before the project and file key are chosen; a missing tail keeps its spelling on its resolved parent, and a file that is itself a link is checked both as the link and as its target. Remote keys lowercase the host only; paths keep their case. Adapter commands run with deadlines (3 s probe, 10 s prompt) and are stopped on daemon shutdown. |
| D56 | push-holds r2 | **Paths resolve physically, cached keys are versioned, adapters run in their own group.** The edit guard and `hold acquire`/`check` resolve a path component by component like the filesystem: symlinks before any later `..`, dangling links to their target, missing tails lexically, then on-disk case (a symlink loop falls back to the path as given). A glob's literal directories are resolved and the pattern kept. Cached repository keys carry a rules version (`v2:`); a row from older rules counts as never computed and is recomputed on next use, with no schema change, so an installed binary is never locked out of the database. Adapter commands run as process-group leaders; a timeout signals the group, and output is collected for at most 250 ms after exit. Hard links stay invisible to the guard. |
| D57 | push-holds r3 | **Case follows the volume, and upgrades restart running processes.** When the requesting project's directory is on a volume that ignores case (detected read-only by looking the directory up under another spelling and comparing device and inode), holds also collide when they match after lowercasing. Folding only adds collisions to the exact comparison and is skipped for patterns with a `[` character class, whose meaning lowercasing would change; a case-sensitive volume compares exactly. A `..` out of a missing directory resumes following links, and a symlink loop falls back to the given path with its longest resolvable leading part canonicalized, so it names the registered project. A process from before a cached-key change misses sibling holds against new-format keys, so the upgrade steps restart every long-running `another` (the daemon, reinstalled if the binary moved, `serve --stdio` clients, remote and hand-run servers) instead of trying to make shipped binaries read both formats. |
| D58 | test fixes | **Automatic holds name literal files only.** Patch headers take precedence over generic path fields, directory hints are skipped, and the core edit guard refuses directories. Every file target, new or existing, is escaped with `globset::escape` before storage; literal escaped patterns compare as literal paths, including on volumes that ignore case. Directory and glob holds remain explicit calls to `hold acquire` or `hold_paths`; their docs warn that every file below a directory is blocked. Block notices explain that worktrees of the same repository still conflict at merge. |
