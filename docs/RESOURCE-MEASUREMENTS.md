# Resource measurements

On 13 November 2026, we sampled an existing Another daemon on a 64 GiB, 12-logical-CPU Apple Silicon Mac running Darwin 27.2.0. The installed CLI reported `another 0.1.0`; this is not a release tag. The daemon had been running for more than two days, so the CLI version does not establish its exact build. These are observations on one machine, not limits or guarantees.

During the preceding hour, `another stats --since 1h` reported 163 holds taken by the edit hook, 10 mid-task notices and 6 Herdr wakes. While that multi-agent workload continued, we took 100 process samples using macOS `ps` (`pid`, `%cpu`, RSS and command), sleeping 0.2 seconds between listings. The existing daemon's RSS ranged from 10,080 to 10,096 KiB (about 9.84 to 9.86 MiB). Its sampled `%cpu` ranged from 0.0% to 10.6%; macOS reports this per logical CPU, so 100% is approximately one fully used logical CPU. These are sampled estimates, not a controlled idle-versus-load benchmark or peak CPU guarantee. The 0.0% observations are quiet samples amid the workload; 10.6% is the highest observed reading. Short-lived hook processes were not captured, so this sampling cannot establish their real-workload peak or frequency.

To measure individual hooks while that machine workload continued, we used the installed CLI with a separate temporary SQLite home and a throwaway Git project. `/usr/bin/time -l` measured one Claude post-tool call with no pending mail and one pre-edit call taking a new path hold. Both commands exited 0, and a subsequent hold listing confirmed the pre-edit hold. The post-tool call reported 10,141,696 bytes (9.67 MiB) maximum RSS; pre-edit reported 11,403,264 bytes (10.88 MiB). Each reported `0.00` seconds real, user and system time at the tool's displayed precision. These were controlled single calls, not naturally sampled hook invocations or sustained-load measurements; startup, contention, concurrent hooks and larger databases may differ.

Another helps agents reuse registered resources, but it does not impose a CPU or memory budget or guarantee that agents will avoid duplicate servers. Holds reduce edit conflicts rather than locking files: shell edits bypass the guard, and the hook fails open if its database is unavailable.
