Inbox or orchestrator

Pass context between agents you already run, or let some other program start them. Those are different jobs.

Getting started Install Full guide Task guides

Keep the product boundary clear

Another supplies shared state for independently run coding agents: path holds that its edit hook enforces for client edits, mail, requests with owners, an activity feed and resource leases. You choose the agents and their work. It does not spawn a team, schedule its tasks or judge its output.

An orchestrator is useful when you want software to start agents and manage a workflow. An inbox is useful when Claude Code, Codex or other clients already run side by side and need to communicate. The two can be complementary.

What Another commits to

Apache-2.0 across the product, with no paid tier. Local-first SQLite state. Vendor-neutral hooks, MCP tools and a CLI. A resource registry for finding and borrowing servers, ports, GPUs, containers and jobs. No product telemetry.

These defaults have limits. Hooks deliver at session start, after the next tool call and at the next prompt, not the instant mail arrives, and an idle agent needs a wake. Wake adapters are optional. Path holds stop a client file edit through the edit hook; an edit from a shell command gets past them. Reaping needs human confirmation on the owning node and is never remote.

Federation is optional and uses a self-hosted hub. The hub can read relayed message bodies; requests remain node-local. There is no built-in TLS. Federation trust model and remote authentication.
