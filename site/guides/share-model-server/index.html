One model server, several agents

Ask what is already running before starting another copy, and leave a record of who is using it.

Getting started Install What is a resource?

What the registry does

Two agents that each need a local model can each start a server and fill your memory. Another keeps a list of what is running, who owns it and who is borrowing it, so an agent can look first.

It is a shared record, and nothing more. Another does not start your server, check that it is healthy or route requests to it, and an agent has to choose to look. Tell your agents to check, for example in your project instructions.

Register what you started

Start your server yourself, then register it. The kinds are model_server, dev_server, port, gpu, container and long_job. These names are examples; use your server's real port and process ID.

another init
another agent register claude --program claude --project .
another agent register codex --program codex --project .
another resource register model_server ollama@11434 --agent claude --endpoint http://127.0.0.1:11434 --purpose "local llm"

Add --pid with your server's process ID so another orphans can match the process. Without one, another reap can't stop the server, and you shut it down by hand. --meta key=value records details such as a model name. --exclusive refuses borrowers, which suits a dev server one agent should own.

Find it and borrow it

another resources -q ollama
another borrow model_server:ollama@11434 --agent codex

The listing shows the endpoint, and the agent connects to that endpoint itself. A borrow lasts 30 minutes unless you pass --ttl. another heartbeat --agent codex and the session hooks renew it. Agents with MCP use resource_find and resource_borrow.

Release it when you finish

another release model_server:ollama@11434 --agent codex
another release model_server:ollama@11434 --agent claude

Releasing ends a lease and does not stop the server. If the owner leaves while others borrow, the oldest borrower becomes the owner. Once the last lease ends, the resource shows as lapsed, and the next agent to borrow it adopts it as owner, so check that it is still answering first. After you really shut it down, the owner runs another release with --stopped.

The session-end hook releases an agent's leases. If your server should outlive the session, end the session by hand with --keep, which holds on to the lease:

another heartbeat --agent claude --end --keep

The resource reference has the details.

Clean up what's left

another orphans
another orphans --no-scan

The first form also scans for listening processes that nothing registered, so it lists things like your editor's helpers and other unrelated tools, along with their full command lines. Those are only candidates. Be careful about pasting that output anywhere, since command lines can contain sensitive values. --no-scan limits it to lapsed resources you registered.

another reap model_server:ollama@11434

Without --confirm, that changes nothing and prints the plan and anything blocking it. A target must have a registered process ID and no live lease, must have been orphaned for the grace period (10 minutes by default) and must belong to you. --confirm sends SIGTERM, and --force adds SIGKILL if the process survives.

The --confirm flag is for people. The MCP tool can only ask for a reap and hand back the command. An agent with shell access could still run that command itself, because the CLI can't tell who typed it, so your client's permission settings are the real boundary.
