A hold says who is in the file

Another records expiring leases on project-relative files or globs. An exclusive hold conflicts with overlapping holds, including holds in other worktrees and clones of the same repository on this machine. Cooperating agents can check that shared state before starting.

With the hooks installed, agents do not have to remember to take holds. Before each file edit, the hook takes a narrow hold on that file for the editing agent, or stops the edit and names the holder when another agent holds it. That covers Claude Code, Codex and Grok CLI; Cursor gets no edit guard. When the hook cannot reach the database it lets the edit through and logs why.

A path hold does not lock the file on disk. An edit made from a shell command, such as sed -i or a script, is not seen by any client's edit hook, so it is neither held nor stopped, and nothing guards a commit. It is not a Git merge strategy either. Split work into separate file scopes, request review without edits when appropriate, and inspect the resulting diff.

Acquire a scope, then check as a peer

Run from one physical repository root. These are demo identities; real sessions should act as their registered identities.

another init
another agent register editor --program claude --project .
another agent register reviewer --program codex --project .
another hold acquire --agent editor --project . 'src/parser.rs' --ttl 1800

Use the project-relative paths you intend to work on. Quote globs such as 'src/**' so the shell does not expand them before Another receives them. This lease lasts 1,800 seconds unless renewed or released.

another hold check --agent reviewer --project . 'src/parser.rs'

While the editor's exclusive hold is live, this reports a conflict and exits with status 3, and the reviewer's client edit to that file is stopped by the edit hook. Coordinate before editing. Checking does not acquire a hold. An acquire batch containing a conflict also exits 3 and grants none of that batch, including its nonconflicting paths.

Renew during work and release at handoff

another hold renew --agent editor
another hold release --agent editor

Without hold IDs, these affect all live holds owned by that agent. Supply specific hold IDs to change only one scope. After release, the peer can check again and acquire its own scope.

Session-start and prompt hooks renew the agent's live holds, and the hook after each tool call renews holds past half their TTL at most once a minute; session-end hooks release them, including the ones the edit hook took. Expired holds stop conflicting. An open terminal does not guarantee those hooks are running; inspect live state with another holds.

Keep the boundary visible

Holds belong to registered projects, and are compared across every checkout of the same repository on this machine, so a hold in one worktree or clone conflicts with the same path in another. Two unrelated repositories never collide. Agents in git worktrees shows what crosses.

Across federated nodes, clashes are warnings, never distributed locks. A successful check reflects state at that moment. Cooperation and review still matter after another agent starts.

Use a Claude Code/Codex handoff to request a review and MCP requests to assign responsibility. For leases on servers or GPUs, see sharing a model server and the resource guide.
