A hold signals intent

Another records expiring leases on project-relative files or globs. An exclusive hold conflicts with overlapping holds. Cooperating agents can check that shared state before starting.

A path hold by itself does not prevent a direct file write. It is not a filesystem lock or Git merge strategy. Split work into separate file scopes, request review without edits when appropriate, and inspect the resulting diff.

Acquire a scope, then check as a peer

Run from one physical repository root. These are demo identities; real sessions should act as their registered identities.

another init
another agent register editor --program claude --project .
another agent register reviewer --program codex --project .
another hold acquire --agent editor --project . 'src/parser.rs' --ttl 1800

Use the project-relative paths you intend to work on. Quote globs such as 'src/**' so the shell does not expand them before Another receives them. This lease lasts 1,800 seconds unless renewed or released.

another hold check --agent reviewer --project . 'src/parser.rs'

While the editor's exclusive hold is live, this reports a conflict and exits with status 3. Coordinate before editing. Checking does not acquire a hold. An acquire batch containing a conflict also exits 3 and grants none of that batch, including its nonconflicting paths.

Renew during work and release at handoff

another hold renew --agent editor
another hold release --agent editor

Without hold IDs, these affect all live holds owned by that agent. Supply specific hold IDs to change only one scope. After release, the peer can check again and acquire its own scope.

Session-start and prompt hooks renew the agent's live holds; session-end hooks release them. Expired holds stop conflicting. An open terminal does not guarantee those hooks are running; inspect live state with another holds.

Keep the boundary visible

Holds belong to registered projects. Separate checkout paths can be separate projects even when they share Git history. Confirm both agents use the intended project before treating a clean check as shared coordination.

Across federated nodes, clashes are warnings, never distributed locks. A successful check reflects state at that moment. Cooperation and review still matter after another agent starts.

Use a Claude Code/Codex handoff to request a review and MCP requests to assign responsibility. Leases for servers or GPUs are documented separately in the resource guide.
