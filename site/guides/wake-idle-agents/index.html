Wake an idle agent at its prompt

Hooks fire on activity. An idle session has none, so something has to type into its terminal.

Getting started Install What is wake?

When you need this

Session hooks deliver a digest at session start and a notice on the next prompt. If an agent has finished and is waiting for you, nothing happens until you type. another wake does that typing, through tmux, cmux or Herdr.

You may not need it. If you check each agent yourself every few minutes, hooks alone are simpler.

Point an agent at its pane

This assumes the agent runs in tmux. Inside that pane, tmux sets TMUX_PANE; from elsewhere, tmux list-panes -a shows pane IDs. The agent codex@shop and the pane %3 are examples, so use your own.

another wake set --agent codex@shop --via tmux --target %3
another wake list

Session hooks running inside tmux or cmux record this automatically, and never replace a target you set by hand. If you've installed hooks and started the session in tmux, check another wake list first; it may already be there.

Preview, then send

another wake --agent codex@shop --dry-run
another wake --agent codex@shop

--dry-run prints the exact tmux commands. The real command types a one-line summary into the pane and presses Enter: counts, up to three subjects and the commands to read them. It never includes message bodies. An agent with nothing unread and no requests waiting on it is skipped unless you pass --force. Waiting requests include open and stale ones addressed to it, and ones it has claimed.

another wake --all

--all wakes each agent that has a stored target and something waiting. That is what you would put in a cron job, since Another has no scheduler of its own.

Limits to plan around

  • It types into whatever is in the pane. Another can't see what the pane is showing. If the agent has exited and left a shell, your shell receives the text and Enter. If you are in the middle of typing there, it joins your line.
  • A busy agent queues it or misses it. What happens depends on your client. Wake doesn't interrupt anything by design.
  • A repeat wake sends again. --all repeats the nudge while anything is still waiting, even after the mail is acknowledged if a request remains, so a one-minute cron job can fill a prompt. Pick a slower interval.
  • It uses your local tmux. Waking across machines isn't part of this. See agents on two machines for what does travel.

We ran the commands above against a real tmux pane running a stand-in program, and the text arrived. How each coding client reacts to typed input while busy was not tested. The wake reference covers cmux, Herdr and the optional Herdr plugin.
