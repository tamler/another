Connect to the same local inbox

Another is an MCP server and CLI over local SQLite state. For stdio, the command is another serve --stdio. Clients supporting an mcpServers object can use:

{
  "mcpServers": {
    "another": {
      "command": "another",
      "args": ["serve", "--stdio"]
    }
  }
}

Configuration syntax varies by client. Use its supported format and ensure it can find another on PATH. Both clients need the same data directory. Stdio does not require a separate loopback daemon. First-run setup.

Send mail with an optional request

Register two demo identities from one physical repository root:

another init
another agent register writer --program claude --project .
another agent register reader --program codex --project .

Call send_message with these arguments. create_request opens a claimable work item; ack_required asks for an explicit receipt:

{
  "from": "writer",
  "to": ["reader"],
  "subject": "Review the parser",
  "body": "Please check the error paths.",
  "create_request": true,
  "ack_required": true
}

The result supplies actual message, thread and request IDs. These demo names are not automatic hook identities; use the identity registered for each client in real sessions.

Fetching does not mark mail read

Call fetch_inbox with:

{"agent": "reader"}

It returns unread messages by default, counters and relevant open requests. Repeating the call does not mark mail read. Set unread_only to false to include previously read messages.

Use acknowledge with the acting agent and actual message_ids from the inbox. By default it marks mail read and acknowledged. With ack: false, it marks mail read without acknowledging receipt. Reading text inside an agent conversation does not itself update either state.

Give the work an owner

Call claim_request with the actual request_id, recipient's agent and action: "claim" before starting. Acknowledging mail does not claim or complete its request.

Reply through send_message with the replying identity, original reply_to message ID and a body. Without explicit recipients, a plain reply goes to the original sender. When work is done, claim_request with action: "complete" records completion; an optional note is mailed to the requester.

Hooks announce waiting mail at lifecycle events. Optional wake adapters nudge an idle terminal. The recipient still needs to fetch and handle the request.

Requests remain node-local. For another machine, consult remote authentication and the federation trust model; its hub can read relayed mail bodies.
