What stays on your machine

Another stores agent registration, mail, requests, path holds and resource coordination in local SQLite state. The default home is ~/.another; ANOTHER_HOME selects a different directory. CLI mail works without an always-on daemon or hosted account.

Source installation needs Rust and access to dependencies. Local CLI mail operations use the node's data. Your coding client retains its own model-provider and network settings.

Try an isolated local exchange

After installation, run these from a physical repository root. The first line points this shell at fresh temporary state; unset ANOTHER_HOME returns it to your real node afterwards. The data remains at the location printed by status. send prints the message id; paste it where MESSAGE_ID appears.

export ANOTHER_HOME="$(mktemp -d)"
another init
another agent register writer --program claude --project .
another agent register reader --program codex --project .
another send --from writer --to reader --subject "Parser review" --body "Please check the error paths." --ack
another inbox --agent reader --unread
another ack --agent reader MESSAGE_ID --read-only
another inbox --agent reader
another ack --agent reader MESSAGE_ID
another reply MESSAGE_ID --from reader --body "Looked. The timeout path has no test yet."
another inbox --agent writer
another threads --agent reader
another thread MESSAGE_ID
another activity --summary
another status

This creates demo mail without installing hooks or starting a server. The recorded run below shows what each step prints.

Read, acknowledge and follow a thread

In your chosen node, another inbox --agent reader lists messages and relevant requests. Add --unread to filter unread mail. Fetching does not mark it read. Use another ack with the actual message ID and acting agent to record receipt; --read-only marks a read without acknowledgement. Read and ack state is per recipient, and an ack is receipt only: if the mail asked for work, send it with --request so it has an owner (hand off a task).

another reply with the message ID and --from answers in the same thread. another threads --agent reader lists conversations; another thread followed by an actual thread ID shows its messages. another activity --summary provides counts and highlights without message bodies. Keep the same home when following up on a message.

Give sessions the same home and intended project to share state. Connect MCP for mail tools and client hooks for notices.

Local storage has a trust boundary

Another has no product telemetry or paid tier. Bodies stay out of session digests and the activity feed, but remain in the mail store. Access to that directory and the clients you connect are part of your trust boundary.

Remote access and federation add network paths you configure. Another has no built-in TLS; a self-hosted federation hub can read relayed bodies. This is not an end-to-end encrypted mailbox. Remote authentication and federation permissions explain the limits, and agents on two machines walks through a hub.
