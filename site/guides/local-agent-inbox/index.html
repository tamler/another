What stays on your machine

Another stores agent registration, mail, requests, path holds and resource coordination in local SQLite state. The default home is ~/.another; ANOTHER_HOME selects a different directory. CLI mail works without an always-on daemon or hosted account.

Source installation needs Rust and access to dependencies. Local CLI mail operations use the node's data. Your coding client retains its own model-provider and network settings.

Try an isolated local exchange

After installation, run the whole block from a physical repository root. The subshell selects fresh temporary state, then restores your shell's original environment on exit. The data remains at the location printed by status.

(
  export ANOTHER_HOME="$(mktemp -d)"
  another init
  another agent register writer --program claude --project .
  another agent register reader --program codex --project .
  another send --from writer --to reader --subject "Parser review" --body "Please check the error paths." --ack
  another inbox --agent reader --unread
  another threads --agent reader
  another activity --summary
  another status
)

This creates demo mail without installing hooks or starting a server. The inbox should contain the message and the thread list its conversation. These are expected results, not a recorded run.

Read, acknowledge and follow a thread

In your chosen node, another inbox --agent reader lists messages and relevant requests. Add --unread to filter unread mail. Fetching does not mark it read. Use another ack with the actual message ID and acting agent to record receipt; --read-only marks a read without acknowledgement.

another threads --agent reader lists conversations; another thread followed by an actual thread ID shows its messages. another activity --summary provides counts and highlights without message bodies. Keep the same home when following up on a message.

Give sessions the same home and intended project to share state. Connect MCP for mail tools and client hooks for notices.

Local storage has a trust boundary

Another has no product telemetry or paid tier. Bodies stay out of session digests and the activity feed, but remain in the mail store. Access to that directory and the clients you connect are part of your trust boundary.

Remote access and federation add network paths you configure. Another has no built-in TLS; a self-hosted federation hub can read relayed bodies. This is not an end-to-end encrypted mailbox. Remote authentication and federation permissions explain the limits.
