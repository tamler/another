Getting started Install Full guide

Use the same project and node

Start both clients from the same physical checkout root. They need the same Another binary and local data directory: ~/.another by default, or the same ANOTHER_HOME value. Different checkout paths can become separate registered projects.

After installation, run from the repository root:

cd "$(pwd -P)"
another init
another agent register claude --program claude --project .
another agent register codex --program codex --project .
another agent list

--project . associates the identity with this checkout. Without it, agent registration is node-wide. Use the actual qualified addresses printed by the list if a bare name is not unique.

Announce waiting mail, and guard edits

another hook install --client claude,codex --dry-run

Inspect the plan, then remove --dry-run when you want to install. This changes user-global client configuration, backs up changed files and preserves existing hooks and permissions. In Codex, review and trust new hooks under /hooks. Start a new session after setup.

The default hook identity is the client name within its project. For multiple sessions of one client, register distinct identities and set ANOTHER_AGENT in each session's environment. Session-start digests, a notice after the next tool call and prompt notices announce waiting work; a busy agent sees it at its next tool call and may handle it later. Before each file edit, the hook takes a hold on that file, or stops the edit when the other agent holds it. Hook identity and lifecycle reference.

Connect the inbox tools

Add another serve --stdio as an MCP server in each client's supported configuration format. Both use the shared local node. MCP messaging explains the tool arguments and state changes.

Hooks supply short digests without message bodies. MCP tools fetch messages, send replies and claim requests. You choose the tasks and run the clients; Another supplies their coordination state.

Make the review handoff explicit

another send --from claude --to codex --subject "Review the parser" --body "Please check the error paths." --request --ack
another inbox --agent codex
another activity --summary

The recipient can fetch its inbox, claim the request before starting, reply in its thread and acknowledge the mail. Completing a request and acknowledging a message are separate operations. This is a workflow to run, not a terminal recording. Hand off a task covers claiming and completing in full.

For review-only work, specify the files and behavior to inspect. If both agents need to edit, agree on separate scopes and let path holds keep them apart; the edit hook stops a client edit to a file the other agent holds. A shared inbox does not merge changes or evaluate the review.
