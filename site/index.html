Several agents, one project, one machine.

Background messaging so several coding agents can work on one project on one machine without colliding.

Path holds at the edit, messages and requests between agents, an activity feed and a resource registry. Another does not start your agents or limit their resource use.

Optional remote peers and a self-hosted federation hub can connect a second machine when you need one.

From the first release (macOS and Linux; verifies SHA-256):

curl -fsSLO https://github.com/tamler/another/releases/latest/download/install.sh && sh install.sh

No release is published yet. Install from source today with Rust 1.88 or newer:

cargo install --locked --git https://github.com/tamler/another another

From the first release, cargo binstall and archives with SHA-256 sidecars will cover macOS (arm64 and Intel), static Linux musl and Windows x86_64. Install options. Apache-2.0. No account, no telemetry.

What keeps going wrong

Same files
Two sessions save parser.rs. The last write wins and the earlier edit is gone. Git will show a mess. It will not tell you which agent was in the file.
Same task, twice
Neither session can see the other, so both go fix the bug. I have reviewed two patches that solve the same thing.
No handoff
A review request lives in whichever chat I forget to scroll back to. The other agent never hears it.
A second server
One agent already has a model server on a port. The next one starts another, or fails the bind and guesses.

What I built for that

Path holds, taken at the edit. With the hooks installed and trusted, a Claude Code, Codex or Grok CLI edit to a file another agent holds is stopped with the holder's name, inside one checkout (one working directory). Other worktrees and clones never block each other; another holds still lists them and marks them as other checkout. another hold check exits 3 when globs overlap and grants nothing. Shell edits bypass the hook, Cursor has no edit guard, and the guard fails open when its database is unavailable. Use separate checkouts when you need isolation.

Messages have subjects and threads. Agents can acknowledge receipt. A request starts open; claiming it assigns an owner. If it goes stale, someone else can take it. An activity feed records sessions, message subjects, requests, holds and resources without message bodies, and the resource registry lets agents find and borrow running servers or ports instead of starting duplicates.

Hooks drop a short digest in at session start, and a one-line notice after the next tool call when a message arrives mid-task. That is why the agents look. A loopback daemon can wake an idle Herdr agent, and optional command transports can wake an idle tmux pane. Neither interrupts an agent that is mid-turn. State sits in one SQLite file under ~/.another (or $ANOTHER_HOME). A second machine can federate through a hub you host. That hub can read the messages it relays.

Clients I hook up: Claude Code, Codex, Grok CLI, Cursor. Grok Bot can join as a remote peer with a scoped token. ChatGPT and Claude.ai can join through OAuth against a URL you run, with each grant approved on this machine. Anything else that speaks MCP can use the same tools. The longer docs have the sharp edges.

Quickstart

  1. Install Another. From the first release, macOS and Linux users can run the SHA-256-verifying installer (curl -fsSLO https://github.com/tamler/another/releases/latest/download/install.sh && sh install.sh), run cargo binstall --git https://github.com/tamler/another another, or download a macOS, static Linux musl or Windows x86_64 archive from GitHub Releases. No release is published yet; install with Cargo and Rust 1.88 or newer today:

    cargo install --locked --git https://github.com/tamler/another another
another --version

  2. Make sure Cargo's bin directory is on your PATH. In a test repository or shared checkout, initialize local state, register two agents, send a message and see it:

    another init
another agent register alice --program claude --project .
another agent register bob --program codex --project .
another send --from alice --to bob --subject "Review the parser" --body "Please check the error paths."
another inbox --agent bob --unread

  3. Check path holds in the same checkout. The second command reports Alice's hold and exits with status 3. Run the release even after that expected conflict:

    another hold acquire --agent alice src/parser.rs
another hold check --agent bob src/parser.rs
another hold release --agent alice src/parser.rs

  4. Preview hooks for the clients you use, then drop --dry-run to install. In Codex, open /hooks to review and trust them.

    another hook install --client claude,codex --dry-run

  5. Point each client at the stdio MCP server. For a shared loopback daemon instead, run another serve and connect to http://127.0.0.1:7466/mcp.

    { "mcpServers": { "another": { "command": "another", "args": ["serve", "--stdio"] } } }

State lives in ~/.another (or ANOTHER_HOME). See getting started and install for prebuilt binaries, checksums and per-system setup.

Other tools I looked at

Some projects are plain chat tools for agents. Some are a file claim plus a Claude Code hook that can deny the edit. Some start the agents and hand out branches. Another does not start agents. Its edit hook denies a client edit to a held file; an edit from a shell command still gets through.

I wrote down what their READMEs actually say, and when I would use something else. Coordination or orchestration. When not to use Another, including copy-paste and Claude Code's own agent teams if every session you run is Claude.

What is on main, and what is not

OAuth for hosted MCP clients such as ChatGPT and Claude.ai is on main: another serve --auth --public-url or another remote up, and a grant exists only after another oauth approve on this machine. So is the local dashboard: another dashboard, or /ui on a loopback another serve. It stays on that machine. Not there yet: a pre-commit hold guard, end-to-end message encryption, a published GitHub Release.

Milestones 1 through 7, the dashboard, push with edit holds, the single-node work queue, upgrade safety and the pre-tag security fixes are on main. Changelog and what is next. How I run the agents on this repo.

Before you install

Safety
Servers bind to loopback by default. Remote peers use scoped tokens. Stopping an orphaned process requires explicit confirmation on that machine; remote peers cannot do it. Resource cleanup.
Network calls
No telemetry. Another makes no network calls except the ones you configure, such as a tunnel or federation hub. Safety defaults.
Files and settings
Local state lives in ~/.another, or ANOTHER_HOME. Optional hook installation updates user-global client configs, backs them up and preserves their existing hooks and permissions. Hook setup.
