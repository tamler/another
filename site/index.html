From one agent to another.

I run Claude Code and Codex in the same repo. They edit the same files, redo each other's work, and the only handoff is me pasting a paragraph from one terminal into the other.

Another puts path holds on the files those sessions edit, so a second agent's edit to a file another holds is stopped with the holder's name. Around the holds: a local inbox with requests that have an owner, a feed of who is doing what, and a registry for ports and model servers, so the next agent borrows the one that is already running. It does not start the agents.

cargo install --locked --git https://github.com/tamler/another another

Rust 1.88 or newer. Apache-2.0. No account, no telemetry.

What keeps going wrong

Same files
Two sessions save parser.rs. The last write wins and the earlier edit is gone. Git will show a mess. It will not tell you which agent was in the file.
Same task, twice
Neither session can see the other, so both go fix the bug. I have reviewed two patches that solve the same thing.
No handoff
A review request lives in whichever chat I forget to scroll back to. The other agent never hears it.
A second server
One agent already has a model server on a port. The next one starts another, or fails the bind and guesses.

What I built for that

Path holds, taken at the edit. With the hooks installed, each file an agent edits gets an expiring hold, and a Claude Code, Codex or Grok CLI edit to a file another agent holds is stopped with the holder's name, across worktrees and clones of the same repo. another hold check exits 3 when globs overlap and grants nothing. An edit made from a shell command gets past the hook, and Cursor has no edit guard, so use another checkout when you need a real boundary.

Mail with a subject, a thread, and an ack. A request has an owner: open, then claimed, then done. If it goes stale, someone else can take it.

Hooks drop a short digest in at session start, and a one-line notice after the next tool call when mail lands mid-task. That is why the agents look. A loopback daemon can wake an idle Herdr agent, and optional wake can type into an idle tmux pane. Neither interrupts an agent that is mid-turn. State sits in one SQLite file under ~/.another (or $ANOTHER_HOME). A second machine can federate through a hub you host. That hub can read the mail it relays.

Clients I hook up: Claude Code, Codex, Grok CLI, Cursor. Grok Bot can join as a remote peer with a scoped token. ChatGPT and Claude.ai can join through OAuth against a URL you run, with each grant approved on this machine. Anything else that speaks MCP can use the same tools. The longer docs have the sharp edges.

About a minute

  1. Install from the lockfile, then make a local node. Rust 1.88 or newer.

    cargo install --locked --git https://github.com/tamler/another another
another init

  2. Preview hooks before they touch your client configs. Drop --dry-run when the plan looks right. Codex still wants you to open /hooks and trust them.

    another hook install --client all --dry-run

  3. Point each client at the stdio server. One shared loopback daemon is another serve, then http://127.0.0.1:7466/mcp.

    { "mcpServers": { "another": { "command": "another", "args": ["serve", "--stdio"] } } }

  4. Register two agents in this checkout, send a request, and take a hold. --ttl is seconds. Exclusive is the default.

    another agent register alice --program claude --project .
another agent register bob --program codex --project .
another send --from alice --to bob --subject "Review the parser" --body "Error paths look wrong." --request
another hold acquire --agent alice src/parser.rs --ttl 1800
another inbox --agent bob

Other tools I looked at

Some projects are inboxes. Some are a file claim plus a Claude Code hook that can deny the edit. Some start the agents and hand out branches. Another does not start agents. Its edit hook denies a client edit to a held file; an edit from a shell command still gets through.

I wrote down what their READMEs actually say, and when I would use something else. Inbox or orchestrator. When not to use Another, including copy-paste and Claude Code's own agent teams if every session you run is Claude.

What is on main, and what is not

OAuth for hosted MCP clients such as ChatGPT and Claude.ai is on main: another serve --auth --public-url or another remote up, and a grant exists only after another oauth approve on this machine. So is the local dashboard: another dashboard, or /ui on a loopback another serve. It stays on that machine. Not there: a pre-commit hold guard, end-to-end mail encryption, a packaged release.

Before you install

Safety
Servers bind to loopback by default. Remote peers use scoped tokens. Stopping an orphaned process requires explicit confirmation on that machine; remote peers cannot do it. Resource cleanup.
Network calls
No telemetry. Another makes no network calls except the ones you configure, such as a tunnel or federation hub. Safety defaults.
Files and settings
Local state lives in ~/.another, or ANOTHER_HOME. Optional hook installation updates user-global client configs, backs them up and preserves their existing hooks and permissions. Hook setup.
