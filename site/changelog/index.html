What shipped

On main as of 16 Nov 2026 (4f77cb6). I checked the repo that day: 0 stars, 1 fork, and no GitHub Release. If those numbers move, this page should move with them.

Install is still cargo install --locked --git https://github.com/tamler/another another with Rust 1.88 or newer. The release workflow can build macOS and static Linux binaries when a v* tag exists. None has been published.

On main

1. Local core
SQLite event log, agents, mail, requests, path holds, MCP over stdio and loopback HTTP, CLI. PR 1.
2. Hooks and the feed
Activity summary, session events, hook packs, another hook install. PR 2.
3. Resources
Shared and exclusive leases, an orphan scan, reap only after a person passes --confirm. PR 3.
4. Remote peer
Scoped bearer tokens, an audit log, GET /activity. Loopback unless you opt into a remote bind. PR 4.
5. Federation
Signed event logs, pairing, hub-and-spoke sync, cross-node mail. Requests stay on one node. PR 5.
6. Wake and release builds
another wake for tmux, cmux, and Herdr. Optional Herdr plugin. Release workflow, quickstart, contributing notes. PR 6.
7. Hosted connectors
OAuth 2.1 on another serve --auth --public-url, so ChatGPT custom connectors and Claude.ai can attach. A grant exists only after another oauth approve on the machine that holds the database. another remote up prints the URL to paste. whats_new for a one-call catch-up. The ChatGPT desktop app on the same machine uses plain stdio or loopback HTTP, with no tunnel. PR 99.
Local dashboard
another dashboard, or GET /ui on a loopback another serve. Agents, holds, mail, requests, resources, and the feed. Message bodies stay on that machine. An authenticated server does not serve it unless you ask, and then it is read-only. PR 100.
Push and enforced holds
A one-line notice after the next tool call when mail lands mid-task. Before each file edit, a hook takes a hold on that file, or stops the edit and names the holder when another agent holds it (Claude Code, Codex, Grok CLI; not Cursor, and not edits made from a shell command). Holds are checked across worktrees and clones of one repository. A launchd daemon on macOS that wakes idle Herdr agents. another stats. PR 103, PR 104, PR 105.
Hold fixes
The edit hook holds the file it edits, never a directory picked up from a tool's path field. Filenames with brackets, braces, stars or question marks are stored literally, and a manual glob still overlaps them. Waits and notices are addressed by agent id, so an ambiguous name can no longer let a conflicting edit through or make every sweep fail. A Done: notice that cannot be delivered never fails a release. PR 137 (from PRs 106, 108, 110, 111, 121 and 124).
Work board
another board and the MCP tool work_board: per project, who holds which paths and until when, which files the edit hook held or stopped recently, and what is waiting on whom. Read-only, no message bodies. The dashboard gains an Edits section. A remote token sees only the one project it names. PR 139.
Federation authority
A signed event from a paired node may now change only objects that node owns: its agents, sessions, mail, deliveries, resources, leases and holds. Before this, a paired spoke could rewrite another node's agent, send mail as it, mark its mail read or take over its leases. A colliding hold id from a peer can no longer change a hold owned elsewhere. PR 133, PR 141.
Safe wake text
A wake types mail subjects into the recipient's terminal. Subjects are now one line of plain text: line breaks, escape and other control characters are refused when mail is sent and when it arrives from a peer, and the text typed by a wake is sanitized, including the \n that cmux send would turn into Enter. PR 146.
Request deadlines
Moving a claimed request's deadline is recorded as request.updated and shown in the activity feed. Releasing a request clears a deadline that has already passed, so it stays open instead of going stale again on its own. PR 148.
CLI
another <name> runs an executable another-<name> from PATH when <name> is not a built-in, the way git does; built-ins always win (PLUGINS.md). Errors print a hint: line naming the command that lists the real ids, and every conflict exits 3. another ack --mark-read-only replaces the misleading --read-only, which still works. PR 153, PR 156, PR 135.
Tested on Windows, timed at scale
Every pull request now runs the test suite on Windows too, not only on Linux. Release binaries are still macOS and Linux only. A performance test seeds 10,000 events and 50 agents and fails if the edit guard, the post-tool mail check, hold checks, the activity summary, the work board or the sweep get slower than set ceilings. PR 132, PR 160.

The project was renamed to Another in PR 8. PR 95 closed token-scope bugs (a remote token could reach outside the projects it was minted for). That fix is on main.

In progress, not merged

Nothing on this page comes from an open pull request. Work that is still in review is not described here until it is on main, because I am not going to describe it as if you can turn it on.

Later, not started here

From the spec, still out of scope for the code on main: a pre-commit hold guard, auto-reap policies, mesh federation, end-to-end mail encryption. The edit hook stops a client edit to a held file, but an edit from a shell command still gets through and nothing guards a commit. Reaping stays a human confirm on the owning machine. I would rather ship those late than pretend a hold is a lock.
