What shipped

On main as of 27 Nov 2026 (commit cb4d1369). No GitHub Release yet. This page lists what is merged to main, not what is in open pull requests.

Install is still cargo install --locked --git https://github.com/tamler/another another with Rust 1.88 or newer. The release workflow can build macOS and static Linux binaries when a v* tag exists. No tag has been cut yet.

Remote peers, hosted OAuth connectors and the loopback dashboard are present on main but frozen for v0.1.0 and treated as experimental. Hub-and-spoke federation between the owner's Mac and VPS is in scope as M9 and required for the tag, including a tested hub backup restore.

On main

1. Local core
SQLite event log, agents, mail, requests, path holds, MCP over stdio and loopback HTTP, CLI. PR 1.
2. Hooks and the feed
Activity summary, session events, hook packs, another hook install. PR 2.
3. Resources
Shared and exclusive leases, an orphan scan, reap only after a person passes --confirm. PR 3.
4. Remote peer
Scoped bearer tokens, an audit log, GET /activity. Loopback unless you opt into a remote bind. PR 4.
5. Federation
Signed event logs, pairing, hub-and-spoke sync, cross-node mail. Requests stay on one node. PR 5.
6. Wake and release builds
Transport adapters (wake, status, list) and a per-user daemon, with a maintained Herdr adapter and a generic command adapter (tmux/cmux by configuration). Release workflow, quickstart, contributing notes. PR 6.
7. Hosted connectors
OAuth 2.1 on another serve --auth --public-url, so ChatGPT custom connectors and Claude.ai can attach. A grant exists only after another oauth approve on the machine that holds the database. another remote up prints the URL to paste. whats_new for a one-call catch-up. The ChatGPT desktop app on the same machine uses plain stdio or loopback HTTP, with no tunnel. PR 99.
Local dashboard
another dashboard, or GET /ui on a loopback another serve. Agents, holds, mail, requests, resources, and the feed. Message bodies stay on that machine. An authenticated server does not serve it unless you ask, and then it is read-only. PR 100.
Push and enforced holds
A one-line notice after the next tool call when mail lands mid-task. Before each file edit, a hook takes a hold on that file, or stops the edit and names the holder when another agent holds it (Claude Code, Codex, Grok CLI; not Cursor, and not edits made from a shell command). Holds are enforced within one checkout; other worktrees and clones never block each other. A per-user daemon on macOS and Linux wakes idle Herdr agents. another stats. PR 103, PR 104, PR 105.
Work queue (v0.1.0)
Admitted queue items (proposed → ready → claimed → done), atomic another queue next, and another needs as the one list of what needs the owner. QUEUE.md, NEEDS.md.
Upgrade safety
A backup before migrate, refusal of unknown schema/table shapes, and a clear split between installed builds and development builds run from a Cargo build directory. DOCTOR.md, VERIFY.md.
Pre-tag security fixes (Q31)
Federation without --auth serves only /fed/* and /health; an explicitly enabled dashboard on an authenticated federation listener requires a token. Wake subjects and edit-denial hold values are quoted and cleaned. Unauthenticated rejection audits are capped at 32 rows per server store per 60 seconds, invalid tokens avoid write transactions, and foreign resource probes use IP literals only with a bounded connect budget outside borrow write transactions. PR 281.
Pre-tag consolidations (FLE-23)
Consolidated crypto helpers with constant-time digest comparison for bearer tokens and queue delegate keys (M-B, PR 283); unified git-root, path resolution and shell_word quoting helpers with physical-parent resolution for missing weak-match directories (M-C, PR 284); and shared test-support helpers for forged wire events in core tests (M-E, PR 282). These three consolidations changed no schema, wire or hook contracts. Later FLE-23 items were admitted on 27 Nov 2026; see the scope update in PR 289.
Metadata flag validation (FLE-23 M-W)
resource register --meta KEY=VALUE shares the parser used by send --field: keys are trimmed and must be nonempty and unique. Missing =, empty keys and duplicate keys are usage errors (exit 2). Previously metadata keys kept whitespace and repeated keys silently replaced earlier values. Metadata values still keep whitespace and further = characters, and may be empty.

The project was renamed to Another in PR 8. PR 95 closed token-scope bugs (a remote token could reach outside the projects it was minted for). That fix is on main.

In progress, not merged

Nothing on this page comes from an open pull request. Work that is still in review is not described here until it is on main, because I am not going to describe it as if you can turn it on.

Later, not started here

From the spec, still out of scope for the code on main: a pre-commit hold guard, auto-reap policies, mesh federation, end-to-end mail encryption. The edit hook stops a client edit to a held file, but an edit from a shell command still gets through and nothing guards a commit. Reaping stays a human confirm on the owning machine. I would rather ship those late than pretend a hold is a lock.
