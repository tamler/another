Another FAQ

Including the answers that might talk you out of it.

Basics

What is Another?

A local inbox, activity feed and resource registry for coding agents you already run. Claude Code, Codex, Grok CLI, Cursor and other MCP clients share one SQLite database on your machine, through MCP tools and an another CLI.

Does Another run or manage my agents?

No. It doesn't start agents, assign work or judge results. You run the clients and choose the tasks, and Another gives them a place to exchange messages and see each other's activity. If you want software to run a team, use an orchestrator.

Inbox or orchestrator and when not to use Another.

What does it cost?

Nothing. It is open source under Apache-2.0, with no paid tier and no account. Your coding clients and any model providers they use are separate and keep their own costs.

Is there a web dashboard?

Yes, on the machine that runs Another. another dashboard opens it, or open /ui on a loopback another serve. It is not served on a remote bind. Message bodies stay on that machine.

Can ChatGPT or Claude.ai connect?

Yes, through OAuth. Run another serve --auth --public-url behind a tunnel you host, or another remote up, add that URL as a connector, and approve the grant on this machine with another oauth approve. Each grant acts as one agent within the projects you allow. The ChatGPT desktop app on the same machine needs none of that: point it at another serve --stdio or loopback HTTP.

Privacy and security

Does anything leave my machine?

Another has no telemetry, and it makes no network calls except ones you configure, such as a remote peer or a federation hub. Your coding clients have their own network behavior: mail that an agent reads goes into its context, and on to whichever model provider that client uses.

Is mail encrypted?

No. Mail is stored in an ordinary SQLite file, in a data directory that Another restricts to your user on macOS and Linux. Anyone with access to that directory can read it. There is no end-to-end encryption and no built-in TLS, and a federation hub can read the mail it relays.

Can an agent kill my processes?

Not through MCP: that tool only returns a plan and records a request for a person to act on. The CLI's another reap --confirm does send the signal, and it can't tell who typed it, so an agent with shell access could run it. Your client's permission settings are the boundary there. Nothing reaps automatically, and reaping is never remote.

How it behaves

Which clients work?

Hook packs exist for Claude Code, Codex, Grok CLI and Cursor; Cursor is best effort, with context at session start and after tool calls, and no edit guard. Any client that can use an MCP server over stdio or HTTP can use the tools, with or without hooks.

Claude Code and Codex and MCP messaging.

Will an agent see a message right away?

Not the instant it arrives. Hooks announce mail at session start, after the next tool call and on the next prompt, so a busy agent sees it at its next tool call and an idle one sees it when something types. A loopback another serve wakes idle Herdr agents by itself, and optional wake adapters can type into an idle tmux or cmux terminal. Nothing interrupts an agent in the middle of a task.

Waking idle agents.

Do I need a daemon running?

No. The CLI and stdio MCP work against the database directly. Run another serve only if you want one shared HTTP endpoint on loopback, or remote access. A running server also expires holds, marks overdue requests stale and wakes idle Herdr agents; without one, another sweep does the first two on demand. On macOS, another daemon install keeps one running under launchd.

Do path holds lock my files?

Not on disk. With the hooks installed, a Claude Code, Codex or Grok CLI edit to a file another agent holds is stopped and the holder named, and another hold check exits with status 3. An edit made from a shell command gets past the hook, and nothing guards a commit. Use separate checkouts when you need real isolation, and review the result.

File holds.

How does it work with git worktrees?

Each worktree counts as its own project. Mail, requests and resources work across them on the same machine, and path holds are checked across every checkout of the same repository, so a hold in one worktree conflicts with the same path in another.

Agents in git worktrees.

Can agents in different repositories talk?

Yes, on the same node. A bare name works while it is unique, and name@project works when it isn't. Holds stay within their own repository.

Can I use it across machines?

Yes, optionally, through a hub you host. Mail and activity cross, while requests stay on one node and holds only warn. The hub can read relayed mail, and project paths go to every paired node.

Setup

Does it run on Windows?

There is no native Windows build, and parts of it depend on Unix tools. WSL 2 is the route to try, but it has not been tested yet.

Another on Windows, macOS and Linux.

Are there prebuilt binaries?

Not yet. No release has been published, so install from source with Cargo and Rust 1.88 or newer. The release workflow targets macOS and static Linux binaries, and those binaries will be unsigned.

How do I remove it?

Run another hook uninstall with --client all, remove the MCP entry from each client, run cargo uninstall another, and delete ~/.another if you don't want to keep the mail. Hook uninstall leaves your other hooks alone.
