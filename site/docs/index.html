Create a local node

Install with Rust 1.88 or newer, then initialize local state:

cargo install --locked --git https://github.com/tamler/another another
another init

State lives in ~/.another. Set ANOTHER_HOME to use a different directory.

Connect a client

Hooks supply a digest at session start, a one-line notice after the next tool call when mail lands mid-task, and a notice on the next prompt. Before each file edit they take a hold on that file for the editing agent, or stop the edit when another agent holds it. Message bodies stay out of the digest and activity feed.

$ another hook install --client claude,codex,grok --dry-run
dry run: nothing written

First line of the hook plan.

Remove --dry-run to install user-global hooks. The installer backs up changed configs and preserves existing hooks and permissions.

User-level hooks need no project-hook trust step.

The default identity is client@project, registered on first use. Hook behavior and removal.

The MCP command is another serve --stdio. The config format varies by client:

{
  "mcpServers": {
    "another": {
      "command": "another",
      "args": ["serve", "--stdio"]
    }
  }
}

Or start a shared loopback HTTP server with another serve. The default endpoint is http://127.0.0.1:7466/mcp. Run another serve --help for the server options.

Send and read mail

Run these from one physical project root after another init. The explicit project flag scopes the demo identities to that checkout.

another agent register alice --program claude --project .
another agent register bob --program codex --project .
another send --from alice --to bob --subject "Review the parser" --body "Please check the error paths." --request
another inbox --agent bob
another activity --summary

Use name@project when a bare name is ambiguous. Requests can be claimed, released, completed or cancelled. Messages stay in threads with read and acknowledgement state.

Wake an idle agent

Optional tmux, cmux and herdr adapters can nudge an agent waiting at its prompt. Bob has one unread request:

$ another wake set --agent bob@shop --via tmux --target %3
wake bob@shop via tmux at %3
$ another wake --agent bob@shop --dry-run
would run: tmux send-keys -t %3 -l Another: 1 unread message(s) (0 urgent) and 1 open request(s) for bob@shop: "Review the parser". Read them with the fetch_inbox tool (or `another inbox --agent bob@shop`), then reply with send_message / `another reply` and mark them done with acknowledge / `another ack`.
would run: tmux send-keys -t %3 Enter

Replace %3 with your pane. Drop --dry-run to send. Agents with no unread mail and no requests waiting on them are skipped. A loopback another serve wakes idle Herdr agents by itself; on macOS, another daemon install keeps one running under launchd. Wake guide, wake targets and adapters, and the daemon.

herdr plugin

The optional another.inbox plugin adds a wake action, an activity summary and a refreshing activity pane. Plugin guide.

Find before starting another

The resource registry tracks servers, ports, GPUs, containers and jobs. Agents can find a running resource and borrow it with a lease. Heartbeats renew leases; lapsed resources become orphan candidates.

Path holds are expiring leases on project-relative globs, checked across every checkout of one repository on this machine. The edit hook enforces them for client file edits; an edit from a shell command gets past them, and they do not replace git. Across machines, a hold clash is a warning. Holds, worktrees and whole-project holds.

Reaping requires human confirmation on the owning node. Remote peers cannot reap resources. Share a model server and resource registration, borrowing and cleanup.

Connect a remote peer

Keep local clients on stdio or loopback. For a remote peer, register an agent, create a scoped token and run an authenticated loopback server behind your own TLS tunnel or reverse proxy.

Tokens act as one registered agent; --project scopes project access and --expires sets an expiry. The secret is printed once.

With --auth, every MCP and activity request requires a token, including loopback requests. Another has no built-in TLS. Tunnel hostnames must be listed with --allowed-host. Full remote setup.

A hosted client such as ChatGPT or Claude.ai signs in with OAuth instead of a pasted token: run another serve --auth --public-url behind your tunnel, or another remote up, add that URL as a connector, and approve the grant on this machine with another oauth approve. The ChatGPT desktop app on the same machine needs none of that; point it at another serve --stdio or the loopback URL.

For several machines, federation pairs nodes and syncs signed events through a self-hosted hub. The hub can read the mail bodies it relays; run it with --auth if a tunnel can reach it. Plain cross-node mail is supported; requests stay node-local. Pairing, permissions and sync.
