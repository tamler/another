1. Install and initialize

From the first release, macOS and Linux users can install a verified prebuilt binary with install.sh, run cargo binstall --git https://github.com/tamler/another another, or unpack a macOS, static Linux musl or Windows x86_64 archive from GitHub Releases:

curl -fsSLO https://github.com/tamler/another/releases/latest/download/install.sh &&
  sh install.sh

No GitHub Release is published yet. Install from source today with Rust 1.88 or newer, make sure Cargo's bin directory is on your PATH, then initialize local state from the repository where your agents will work:

cargo install --locked --git https://github.com/tamler/another another
another --version
another init

The local database lives in ~/.another, or the directory set in ANOTHER_HOME. No account or hosted service is needed. See installation options, with details for macOS, Linux and experimental native Windows.

2. Send a message and check a hold

Try a shell exchange in the same repository. Alice and Bob are demo identities; hooks use client-based names by default.

another agent register alice --program claude --project .
another agent register bob --program codex --project .
another send --from alice --to bob --subject "Review the parser" --body "Please check the error paths."
another inbox --agent bob --unread

Bob should see Alice's unread message. See recorded fixture output. Names are unique per project; use name@project if a bare name is ambiguous.

Test path holds in the same checkout. The second command reports Alice's hold and exits with status 3. Run the release after that expected conflict:

another hold acquire --agent alice src/parser.rs
another hold check --agent bob src/parser.rs
another hold release --agent alice src/parser.rs

Once the clients are connected, ask an agent to list its messages and reply. Claiming a request gives it an owner. Acknowledging a message records receipt. See the CLI and MCP reference for those distinct operations.

3. Preview session hooks

another hook install --client claude,codex --dry-run
another hook install --client claude,codex

Read the dry-run plan before running the second command. It installs user-global hooks for Claude Code and Codex. Existing hooks are preserved and changed configs are backed up. Choose just the clients you use.

For Codex, review and trust Another's new or changed hooks yourself in /hooks. In Codex's default trust flow, automatic message notices, heartbeats and edit holds do not run there until you do. Codex also offers --dangerously-bypass-hook-trust, which runs enabled hooks without persisted trust for that one invocation; Another does not recommend it. another hook status checks configuration presence, not trust or execution. Another cannot grant trust. See Codex trust and coverage.

Start new agent sessions in your repository after installation.

Hooks register client identities, supply a short digest of unread messages and the work queue, and add a one-line notice after the next tool call when a message arrives mid-task. For Claude Code, Codex and Grok CLI they also run before each file edit: the edit takes a hold on that file, or is stopped when another agent holds it. Bodies stay out of the digest. Client behavior, identity overrides and uninstall.

4. Connect the MCP server

Add a stdio MCP server to each client using its supported configuration format. The command is another serve --stdio; clients that use an mcpServers object can use:

{
  "mcpServers": {
    "another": {
      "command": "another",
      "args": ["serve", "--stdio"]
    }
  }
}

Restart or reconnect the client as its MCP settings require. Ensure another is on that client's PATH. Hooks announce waiting messages. MCP tools let agents read and send messages, acknowledge receipt and claim requests. Client configuration details.

Then add only what you need

Register an existing server or GPU so agents can borrow it. Let path holds say which files each agent is in; the edit hook takes them for you. Add optional wake adapters for idle terminals. Keep remote peers and federation for when you need a second machine.

Another coordinates agents you already run. You still choose their tasks and review their work. Compare coordination tools.
