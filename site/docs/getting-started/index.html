Getting started Install Full guide Task guides

1. Install and initialize

With Rust 1.88 or newer installed, run these commands from the repository where your agents will work. Allow extra time for the initial compilation; the following setup is the first five minutes after installation.

cargo install --locked --git https://github.com/tamler/another another
another init

The local database lives in ~/.another, or the directory set in ANOTHER_HOME. No account or hosted service is needed. See installation options, with prerequisites for macOS and Linux.

2. Preview session hooks

another hook install --client all --dry-run
another hook install --client all

Read the dry-run plan before running the second command. It installs user-global hooks for Claude Code, Codex, Grok CLI and Cursor. Existing hooks are preserved and changed configs are backed up. You can choose a single client instead of all.

In Codex, review and trust the new hooks under /hooks. Cursor integration is best effort: context arrives at session start and after tool calls; prompt hooks renew holds; there is no edit guard. Start a new agent session in your repository after installation.

Hooks register client identities, supply short inbox/activity digests, and add a one-line notice after the next tool call when mail lands mid-task. For Claude Code, Codex and Grok CLI they also run before each file edit: the edit takes a hold on that file, or is stopped when another agent holds it. Bodies stay out of the digest. Client behavior, identity overrides and uninstall.

3. Connect the MCP inbox

Add a stdio MCP server to each client using its supported configuration format. The command is another serve --stdio; clients that use an mcpServers object can use:

{
  "mcpServers": {
    "another": {
      "command": "another",
      "args": ["serve", "--stdio"]
    }
  }
}

Restart or reconnect the client as its MCP settings require. Ensure another is on that client's PATH. Hooks announce waiting mail; the MCP tools read, send, acknowledge and claim it. Client configuration details.

4. Send a request

Try a shell exchange in the same repository. Alice and Bob are demo identities; hooks use client-based names by default.

another agent register alice --program claude --project .
another agent register bob --program codex --project .
another send --from alice --to bob --subject "Review the parser" --body "Please check the error paths." --request
another inbox --agent bob
another activity --summary

Bob's inbox should show the unread message and an open request. This is an expected result, not a captured run. See recorded fixture output. Names are unique per project; use name@project if a bare name is ambiguous.

In an agent session, ask the recipient to fetch its inbox, read the request and reply. Claiming a request gives it an owner; acknowledging mail records its receipt. See the CLI and MCP reference for those distinct operations.

Then add only what you need

Register an existing server or GPU so agents can borrow it. Let path holds say which files each agent is in; the edit hook takes them for you. Add optional wake adapters for idle terminals. Keep remote peers and federation for when you need a second machine.

Another coordinates agents you already run. You still choose their tasks and review their work. Compare inboxes and orchestrators.
