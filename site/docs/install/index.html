Install with Cargo

You need Rust 1.88 or newer and its Cargo tool. The supported source install is:

cargo install --locked --git https://github.com/tamler/another another
another --version
another --help

Cargo normally installs into ~/.cargo/bin. Include that directory in PATH for both your terminal and your coding client. For updates from the repository, repeat the install command with --force.

Build from source

git clone https://github.com/tamler/another
cd another
cargo build --release --locked
./target/release/another --version

The binary is target/release/another. Put it in a directory on your PATH, or configure your MCP client with its absolute path. A source build is a way to inspect and edit the same code you run.

Release archives

When v0.1.0 is published, GitHub Releases is the place to get prebuilt archives and SHA-256 checksums. Until the release is available, use Cargo or build from source.

The release workflow targets macOS Apple Silicon and Intel, plus static musl Linux binaries for x86_64 and arm64. After publication, choose the archive for your operating system and architecture, verify its checksum and unpack it, then put another on your PATH. The planned binaries are unsigned; a matching checksum establishes byte integrity against the chosen checksum file, not publisher identity or a signature. Use the project's own release source.

On macOS, a downloaded binary you have verified may need its quarantine attribute removed:

xattr -d com.apple.quarantine ./another

If the attribute is absent, this command may report that there is no such attribute. Source builds through Cargo do not need this download step.

Verify a release archive

Archives are named another-<version>-<target>.tar.gz. The target is aarch64-apple-darwin, x86_64-apple-darwin, x86_64-unknown-linux-musl or aarch64-unknown-linux-musl. An archive's checksum is in a file with the same name plus .sha256, or on its line in a shared SHA256SUMS file.

Put the archive and either checksum file in one folder and change to that folder. Set archive on the first line to your file's name, then paste:

archive=another-0.1.0-aarch64-apple-darwin.tar.gz
if [ -f "$archive.sha256" ]; then sums="$archive.sha256"; else sums=SHA256SUMS; fi
line=$(awk -v file="$archive" '$2 == file && length($1) == 64 && $1 !~ /[^0-9a-fA-F]/' "$sums")
if [ -z "$line" ]; then
  echo "No valid checksum for $archive in $sums"; false
elif command -v sha256sum >/dev/null 2>&1; then
  printf '%s\n' "$line" | sha256sum -c -
else
  printf '%s\n' "$line" | shasum -a 256 -c -
fi && tar -xzf "$archive" && echo "Verified and unpacked: $archive"

It uses sha256sum where that is installed and shasum -a 256 otherwise. It checks only your archive's line, so other archives listed in SHA256SUMS need not be present.

A match prints your archive's name followed by OK, then unpacks it into a folder of the same name. If you see FAILED, or an error about a missing file or checksum line, nothing is unpacked. Stop there and delete the download; do not install it.

No release exists yet, so this snippet has only run against local fixture archives built the way the release workflows build theirs. Every site build repeats that test.

Replace a binary safely on macOS

Remove the old executable before copying the replacement into its place. Overwriting it in place can leave a stale code signature cached and cause macOS to kill the new process at launch. Cargo's installer handles replacement safely.

Replace the executable only. Keep ~/.another (or your ANOTHER_HOME) intact: that directory contains your node's data. Stop and restart your own Another daemon after updating so it uses the new binary.

Check your first run

another --version
another init
another status

If your client cannot find the binary, compare its configured command and PATH with the working terminal. Then connect hooks and MCP and send your first message.
