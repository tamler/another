Another concepts

What each word means in Another, and what it does not promise.

Identity Mail Coordination Awareness Other machines

Identity and scope

Agent
A named identity that sends and receives, such as codex@shop. Another records identities; it does not start or run the agent behind one. Names are unique per project.
Project
A registered directory path with a short slug. Two checkouts of one repository are two projects, with slugs like shop and shop-2 if their folders share a name. See agents in git worktrees.
Address
name works when it is unambiguous, name@project names an agent in a project, and name@project@node reaches another node. Agents registered without a project are node-wide. A bare name registered in two projects stops resolving; a recorded run shows the error and the fix.
Node
One data directory with its own SQLite database and signing key: ~/.another by default, or ANOTHER_HOME. Sessions share state by sharing a node.

Mail

Message
An immutable note with a subject, a body and recipients. Each recipient has separate read and acknowledgement state.
Thread
A conversation of messages. Replies stay in the thread of the message they answer.
Acknowledgement
A recorded receipt, made with another ack or the acknowledge tool. Fetching an inbox changes nothing. An acknowledgement says the mail was received; it does not say the work was done.
Request
A claimable piece of work opened alongside a message. It moves through open, claimed and done, can be cancelled by its creator, and goes stale past its due time. Requests stay on one node. See handing off a task.

Coordination

Path hold
An expiring, advisory claim on project-relative files or globs. Cooperating agents check holds before editing, and a conflict exits with status 3. A hold does not stop any write. See file holds.
Resource
A registered model server, dev server, port, GPU, container or long job, addressed by ID or by kind:name. Another lists it; it does not start it. See sharing a model server.
Lease
A time-limited claim on a resource, held as owner or borrower. The default is 30 minutes. Heartbeats renew it, and if the owner leaves while others borrow, the oldest borrower becomes the owner.
Orphan
A candidate for cleanup: a registered resource with no live lease, or a listening process that nothing registered. A listed process is only a candidate and may be something you want running.
Reap
Stopping an orphan with another reap --confirm, on the machine that owns it, after a grace period. Without --confirm it only prints a plan. The MCP tool can only request it, and nothing reaps automatically.

Awareness

Hook
A user-global entry in a coding client's config that runs Another at session start, on each prompt and at session end. It is how an agent learns about mail without polling. See the hook reference.
Digest
The short inbox and activity summary a hook gives a session. It never includes message bodies.
Activity feed
A readable record of who did what: sessions, mail subjects, requests, holds and resources. Message bodies stay out of it.
Event log
The signed, append-only record behind everything. Query tables are built from it, and it is what federation syncs.
Wake
An optional nudge typed into an idle agent's terminal through tmux, cmux or Herdr. See waking idle agents.

Other machines

Token
A bearer secret that lets one remote client act as one agent within chosen projects, printed once. Every call made with a token is audited.
Federation
Several nodes exchanging signed events through a hub. Each node stays authoritative for its own agents, holds and resources. It is optional. See agents on two machines.
Hub
A node you host that relays events between paired nodes. It can read the mail it relays, so it is not end-to-end encrypted.
Spoke
A node that dials out to the hub to push its events and pull the ones meant for it: directory entries, mail for its agents and, with permission, activity. It needs no inbound port.
