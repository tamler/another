How I run the agent team

This repository is built by more than one coding agent at a time. Claude Code in one checkout, Codex in another, Cursor cloud agents when I point them at a branch. Another does not launch them. I do. Another is the inbox they share.

Public numbers, looked up 10 Nov 2026 on github.com/tamler/another: 0 stars, 1 fork, no GitHub Release. I am writing that down so the story does not grow a user count I do not have.

The loop

Each session registers with its own name. If two Claude Code sessions both show up as claude@repo, their mail and holds collapse together. That one bit me.

another agent register claude-a --program claude --project .
another agent register codex-b --program codex --project .

Before a session edits a file another agent might touch, it takes a hold. TTL is seconds. Exclusive is the default.

another hold acquire --agent claude-a crates/another/src/serve.rs --ttl 1800 --reason "startup line"

A conflicting check exits 3 and grants nothing. The other process can still write the file. I keep a second git checkout when the overlap is real, and I still read the diff. The hold tells the other agent the path is taken.

Handoffs are requests, not a scratch markdown file. I used the markdown file. It went stale the same day.

another send --from claude-a --to codex-b --subject "Review the parser" --body "Error paths look wrong." --request
another inbox --agent codex-b

Hooks are what make the second session notice. another hook install --client all edits user-global client config, keeps a backup, and leaves hooks you already had. Run it with --dry-run first. Codex will not run the new hooks until you trust them in /hooks.

Things I had wrong

Wake
I pointed another wake at an agent that was mid-edit. Nothing useful happened. Wake types into an idle tmux, cmux, or Herdr target, and it skips the agent when the inbox is empty. It does not cut into a running turn.
Reap
another reap without --confirm is a plan. With --confirm it signals a process on that machine. A remote token cannot do it. I do not want a peer box killing a local server.
Federation
The hub I would host can read mail it relays. There is no end-to-end encryption. Requests do not move nodes. I say that in the docs because it is easy to skim past.
Dashboard
another dashboard opens the loopback page. another serve also has it at /ui when it is not an authenticated remote server. OAuth for ChatGPT and Claude.ai is still not merged. That one is on the changelog.

What I will not claim

No download count, no "teams using it", no time saved. The evidence you can check is the merged milestones and the open issues. On 10 Nov 2026 the open docs issues included 26, 27, and 28.
